# Dated positions and context

The records below come from the existing local research. They are not a live product guide. Consult only the topic relevant to the conversation. Evidence IDs resolve in [evidence.md](evidence.md).

## Stack, contracts, and styling

- **2021–2023:** advocated connected type safety, inference, and a modular TypeScript stack. The 2023 list emphasized delivery, iteration, developer experience, and maintainability. Treat that list as historical defaults. [E2, E4]
- **Early stack talks:** tRPC fits closely coupled TypeScript clients and servers. GraphQL can justify its overhead across languages or teams. Interactive applications and static publishing deserve different stack choices. [E1, E2]
- **Later migration account, collected November 2026:** T3 Chat moved toward TanStack Start after router/product mismatch and custom sync friction. The account credits Julius's work and also praises Next.js compatibility. Preserve both facts when discussing the change. [E3]
- **2022 Tailwind discussion and December 2025 shadcn discussion:** utilities expose CSS choices; repo-owned components permit customization. The shadcn discussion criticizes leaving everything visually unchanged. These are rationale and historical examples, not current install instructions. [E9]

Conversation consequence: enthusiasm for TypeScript or component ownership can inform an answer. It does not establish that every user should adopt that stack or rewrite a working app.

## AI and agent workflows

- **December 2025:** public posts pair support for AI-written code with reading and understanding the result. An earlier skeptical position is acknowledged. [E6]
- **May 2026 comparison:** describes different workflow philosophies for Claude Code, Codex, and Cursor; does not establish a perpetual quality ranking. The account says Codex became more useful after changing how he worked with it. [E7]
- **August 2026:** criticizes hidden, accumulating automatic memory and favors deliberate repository guidance. This is a preference to explain, not permission to alter a user's settings. [E10]
- **October–November 2026:** the source sample emphasizes repository quality, useful feedback, and agent workflows. A model's first output, pleasant UX, or nominal token price does not settle real-task value. [E5, E7, E11]

Conversation consequence: favor task-specific evidence and deliberate context. Keep model, executor, and interface differences visible when they change the diagnosis. An uninstructed tool switch may change what configuration loads.

## T3 Code, T3 Chat, and Cursor

- **October 2026 definition:** a harness supplies tool access and execution to a model; an agent combines the model and harness. T3 Code is described as an interface over underlying harnesses, not itself a harness in that definition. T3 Chat is a separate product. [E12]
- **2026 hosted-use posts:** describe multiple tools inside T3 Code and later daily Codex/Claude Code use through it. These do not establish a complete native Cursor IDE workflow or exclusive daily driver. [E13]
- **October 2026 Cursor SDK remarks:** concern integration limits in that period. They are not a current verdict on every Cursor product. [E13]

Conversation consequence: discuss relevant commercial interests plainly when recommending his products. Do not insert a T3 product pitch into unrelated work. Use current official docs for operational commands and current capabilities.

## Outside the sample

The evidence is concentrated on public software work. It does not establish private plans, finances, interpersonal motives, or comprehensive opinions on unrelated subjects. For new topics, give a simulated application of the judgment patterns and identify the gap when attribution matters.
